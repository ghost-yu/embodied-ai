## 1. π₀解决什么问题

动作逐维 token 生成方便复用语言模型，但高频、连续、灵巧控制希望一次输出整段动作分布。π₀结合预训练 PaliGemma 的视觉语言能力和专门的 action expert，用 conditional flow matching 生成动作块。

贡献有架构和训练recipe两条线：约3B VLM加约300M动作专家；跨机器人广泛pretraining与高质量post-training。单一任务演示视频不能说明全部泛化能力；高层语言策略指导的实验也不能算全部任务都由一个低层模型独立规划。

地图：§III/Figure3为总体框架；§IV/PDF4–5页给动作块、flow loss和积分；§V讲数据/训练；Figure7为out-of-box比较；Figure8/9讲语言条件和高层指导；后续图讲新灵巧任务和复杂任务；附录B–D给架构、baseline与推理细节。

## 2. 架构、变量与Figure3【必须会】

观察 $o_t=[I_t^1,\ldots,I_t^n,\ell_t,q_t]$：图像通常2或3视角，ℓ为语言，q为本体关节状态。输出动作块 $A_t=[a_t,\ldots,a_{t+H-1}]$，原论文H=50。t是机器人时间；τ∈[0,1]是生成模型时间。

图像→视觉encoder→VLM embedding；语言→token embedding；状态与带噪动作→action expert的token输入。此处“token”是序列位置概念，可以装连续向量，不一定是离散词表ID。action expert使用单独参数，在共享注意力架构中读取语义信息；不能简单画成LLM完成文本回答后才调用一个完全独立黑盒动作头。

|变量|类型与shape|用途|
|---|---|---|
|images|浮点图像，按相机组织 `[B,H_img,W_img,3]` 等实际预处理布局|视觉prefix|
|语言ids/mask|整数/bool `[B,L]`|文本prefix与有效token|
|state|浮点 `[B,D_s]`|suffix状态位置；按配置padding|
|actions/noise/x_t|浮点 `[B,H,D_a]`|flow训练与采样|
|time|浮点 `[B]`→`[B,1,1]`|每样本生成时间，沿H和D广播|
|v_t|浮点 `[B,H,D_a]`|预测向量场，与动作同shape但不同含义|

代码有统一padding维，不能将模型action_dim当作机器人的实际自由度。原始π₀与后续π₀.5/FAST有不同处理，保存commit的 `pi0.py` 包含变体分支，阅读原论文需锁定原始配置。

## 3. 原论文flow matching逐步计算

原论文§IV给出：

$$A_t^\tau=\tau A_t+(1-\tau)\epsilon,\quad\epsilon\sim\mathcal N(0,I),\qquad u(A_t^\tau|A_t)=A_t-\epsilon.$$

τ=0是纯噪声，τ=1是示范动作。A是干净动作块，ϵ是标准高斯块，u是连接两端的速度向量。它不是末端物理运动速度，而是**动作表示空间随生成时间变化的方向**。

$$L_\tau(\theta)=\mathbb E_{p(A_t|o_t),q(A_t^\tau|A_t)}\|v_\theta(A_t^\tau,o_t)-u(A_t^\tau|A_t)\|^2.$$

θ为网络参数，vθ预测向量场。学习不同观测下从噪声到动作分布的路径。训练随机选τ，给出中间混合动作和条件，计算平方误差；推理没有真实A，需要积分预测v。

数值例：A=0.2、ϵ=1、τ=0.25，则Aτ=0.8，u=−0.8。若v=−0.7，平方误差0.01。训练不是让v输出动作0.2，也不是输出噪声1。

原文还写 $q(A_t^\tau|A_t)=\mathcal N(\tau A_t,(1-\tau)I)$，而其显式采样式的噪声系数为1−τ，按通常“第二参数是协方差”约定应得到 $(1-\tau)^2I$。这里记录原文表述差异，不静默替换；后续解释以显式采样式及实际代码为准。

Euler采样：$A_t^{\tau+\delta}=A_t^\tau+\delta v_\theta(A_t^\tau,o_t)$。δ=0.1、十步，从噪声到动作。若理想常向量−0.8，从1每步减0.08，十步到0.2。该直线路径小例不表示真实神经网络每一步预测同一个常数。

【必须会】区分物理时间t、flow时间τ、动作块位置；理解loss target与Euler更新。【建议会】路径分布与训练τ采样分布，以及为什么神经向量场可以表达多模态。

## 4. 当前代码使用相反时间：不能抄错符号

实际 `Pi0.compute_loss` 关键代码：

```python
time_expanded = time[..., None, None]
x_t = time_expanded * noise + (1 - time_expanded) * actions
u_t = noise - actions
```

代码时间记s以免与机器人t混淆：s=1噪声，s=0动作。换元s=1−τ，就得到代码目标u_s=ϵ−A，与原论文uτ=A−ϵ符号相反。两个参数化可以一致，但训练目标和积分方向必须同时改变。

代码推理 `dt=-1/num_steps`，从 `(noise,1.0)`开始，更新 `x_t + dt*v_t`，所以v即使是+0.8，dt=−0.1仍每步减0.08。若错误地套论文正dt，会朝噪声外侧移动。源码注释明确说明使用与论文相反的约定。

`compute_loss(rng,observation,actions,train=False)`：rng是JAX随机key，split产生预处理/噪声/时间各自key；actions为`[*B,H,D_a]`。time来自beta(1.5,1)，再映射到[0.001,1)；不是均匀τ采样。prefix/suffix合并forward，action_out_proj取最后H个位置，`mean(square(v-u),axis=-1)` 返回 `[*B,H]`，**不是这个函数内已平均所有轴的标量**，上层训练再汇总。

这是JAX实现，不是PyTorch `nn.Module.forward`。JAX随机数是显式key管理，不能按PyTorch全局seed机制逐行类比。当前仓库另有PyTorch实现，此文核心映射锁定已读的JAX文件。

## 5. Prefix缓存和双向动作注意力

`Pi0.sample_actions(rng,observation,num_steps=10,noise=None)` 返回 `[B,H,D_a]`。noise若提供可固定初始条件，None则采高斯。先embed_prefix，forward得到kv_cache；每一步只更新suffix，suffix queries读取prefix+suffix的keys/values。full_attn_mask为 `[B,N_suffix,N_prefix+N_suffix]`，代码有形状assert。

图像/文本prefix不依赖当前flow时间，因此可缓存；带噪动作每步改变，不能缓存成不变输出。动作chunk内部可双向attention，以协调多个未来动作；这不同于语言token逐个因果生成。while_loop维护 `(x,time)`，不更新模型权重，停止条件考虑浮点误差。

执行链：`scripts/train.py`→training config→data_loader和transforms→模型构造→compute_loss→optimizer；推理经 `policies/policy.py`→Observation转换→sample_actions→输出transforms→机器人动作。数据中的绝对/相对动作变换、标准化和padding决定部署能否正确。

## 6. 数据recipe与实验解释

Pretraining覆盖更广的任务、机器人与恢复行为；post-training用更连贯的高质量示范磨练特定复杂操作。只用“最好看”的演示可能缺少偏离轨迹后的纠正行为；这只是recipe动机，不是说质量差的数据一定越多越好。

Figure7/PDF8页比较五类任务的 Average Task Progress，而不是所有任务的二元成功率。完整π₀训练700K updates，parity版160K以匹配baseline updates；OpenVLA还分别有全数据与UR5e-only列，Octo等baseline的输入/动作表示也不同。原图未在每根柱上标精确值，此文不把读图估值写成论文精确数字。趋势是完整π₀及parity版领先，但模型大小、初始化和训练目标并非仅一个受控因素。

Figure8说明bussing、table setting、grocery bagging三种语言评估。任务被分成约两秒的语言segments；Figure9每任务10次，区分π₀-flat（整任务指令）、π₀-human（人给中间指令）、π₀-HL（高层VLM给中间指令）。接受人类中间指令的表现不能叫完全自主任务成功；高层指令也是另一个模型的贡献。

π₀-small=470M且无VLM初始化，主模型约3.3B。正文明确承认尺寸与初始化因素有混淆，不能从两者比较精确量化“VLM预训练单独贡献了多少”。复杂任务展示支持本文设置的灵巧性，不证明跨任意机器人零样本可用。

## 7. 从 Pi0Config 到专家注意力的真实对象【必须会】

本篇锁定原始π₀：`Pi0Config(pi05=False)`，默认action_dim=32、action_horizon=50、max_token_len=48、PaliGemma为gemma_2b、action expert为gemma_300m。默认pi05=False时state是连续suffix token，时间与action embedding拼接后经过MLP；pi05=True才改为离散state输入与adaRMSNorm时间条件。不能把同一个文件里的变体分支都当作原论文结构；FAST是另一个文件和动作表示。

JAX/Flax对象与PyTorch不同：`Pi0`继承BaseModel，内部有NNX Linear；旧Linen Gemma/SigLIP通过 `nnx_bridge.ToNNX` 转入NNX对象图。`llm.lazy_init(...,method='init')` 初始化参数结构，不是下载预训练权重。`config.create(jax.random.key(seed))` 默认随机初始化，要具备预训练语义还需加载真实checkpoint。`nnx.state(model,nnx.Param)`提取参数，`nnx.value_and_grad`构建loss与梯度，Optax/NNX optimizer更新权重。JAX显式key决定随机数，使用同一key通常会重现同一noise/time，不应在每步无意复用。

真实配置的语言宽度2048、动作专家宽度1024，深度均18；两者有8个query heads、1个KV head、每头256维。**hidden_size/num_heads不等于这里的head_dim**：动作专家1024维通过自己的投影映射到8×256的query空间。两个专家可以有不同输入宽度，但Attention要求它们的head_dim、query head数、KV head数一致，以便拼接attention所用张量。

`gemma.Attention.__call__(xs,positions,attn_mask,kv_cache)`中xs是一组专家token数组或None。每个专家用自己的q/kv投影，之后沿token轴拼接所有专家的q/k/v；对q/k应用RoPE，q乘head_dim的逆平方根；有cache时，将缓存k/v与当前suffix k/v拼接。最后attention结果按专家各自token长度切回，再用各自输出投影回自己的宽度。并不是专家权重完全共享；也不是动作网络先读取一段LLM生成的文字回答。

小配置两个专家宽度64、深度4，8 query heads、1 KV head、head_dim16；q形状`[B,N,8,16]`，k/v为`[B,N,1,16]`，属于grouped/multi-query注意力。prefix与suffix拼接后，attention mask决定哪些连接能使用。原模型expert宽度不同与demo相同宽度的差别已经明确，demo不能证明3.3B尺度的质量。

## 8. embed_prefix/ suffix：连续 token 如何进入模型【必须会】

`embed_prefix(obs)`为Pi0实例方法，obs是Observation对象，含images/image_masks/state/整数prompt/mask。它按images字典的顺序执行官方SigLIP，取`pool_type='none'`的patch序列，再拼语言embedding。每张图image_mask `[B]`重复到该图所有patch位置；文本mask保留padding有效性。返回 `(tokens,input_mask,ar_mask)`。ar_mask的prefix部分全False，所以有效图像和文本在prefix内双向交流，不生成因果语言回答。

原So400m/14在224×224图上产生16×16=256个patch；三相机加48个prompt位置，prefix长度为768+48=816（语言padding仍占张量位置，但mask为False）。本demo将**实际官方SigLIP的构造配置**改为mu/32，每图7×7=49个patch，三相机147+4=151个prefix位置。不是直接提供假视觉token绕开编码器，图像仍经过官方Conv/视觉Transformer/projection；同时这里没有So400m预训练视觉能力。

`embed_suffix(obs,noisy_actions,timestep)`在原始π₀分支产生一个state token与H个action token。state `[B,32]`经state_proj变成`[B,1,d_e]`；带噪actions `[B,50,32]`经action_in_proj变成`[B,50,d_e]`。timestep `[B]`经posemb_sincos变成`[B,d_e]`，重复50个位置。拼接action与time在最后一维得到`[B,50,2d_e]`，经过Linear→swish→Linear回到`[B,50,d_e]`，不额外新增一个时间token。suffix最终为`[B,51,d_e]`。

`posemb_sincos(pos,embedding_dim,min_period,max_period)`是模块函数，输入一维浮点pos，返回偶数维正弦/余弦向量；odd embedding_dim抛ValueError。embedding中的“频率”是编码flow时间的基函数尺度，不是机器人控制Hz。np/jnp的`[...,None,None]`在尾部加两个长度1的轴，才能把每样本time广播到H与动作维。

## 9. 用累加分组读懂注意力 mask【必须会】

`make_attn_mask(input_mask,mask_ar)`是模块函数，不是模型方法。`input_mask`表示真实token是否有效；`mask_ar`表示当前token开始新attention组。它先对mask_ar累加，得到group id，然后允许**key的group≤query的group**，最后同时屏蔽padding queries与keys。返回bool `[B,N,N]`，True表示连接允许。

原始π₀的三个组：图像/语言prefix为组0；state开始组1；第一动作开始组2，剩余49动作与它同组。因此：prefix只能读prefix；state可以读prefix与state；全部动作能读prefix、state和所有动作，动作块内部双向。这不是把“suffix全双向”一笔带过：state token不能读取action tokens。

小例：prefix有三个位置p0,p1,pad，接state与两个action。mask_ar=[0,0,0,1,1,0]，group=[0,0,0,1,2,2]。input_mask=[1,1,0,1,1,1]。a0能读p0、p1、state、a0、a1，不能读pad；state不能读a0/a1。`cumsum[:,None,:] <= cumsum[:,:,None]`的右边是query组、左边是key组，颠倒这两个轴会反过来泄漏suffix信息给prefix。

## 10. 缓存推理为何应与完整前向一致【建议会】

训练可一次把prefix/suffix传入LLM；推理先用 `[prefix,None]`填KV cache，之后用 `[None,suffix]`计算动作专家。prefix不能读suffix，且图像/文本不随flow时间变，所以每一步prefix的keys/values可复用。suffix的state和带噪action每一步仍重新嵌入，不能缓存为固定动作输出。

缓存调用的query只有51个suffix位置，但key/value有151+51=202个位置。prefix读取许可由prefix_mask沿suffix query轴重复；suffix内部仍按三组规则裁出后两组。位置为`sum(prefix_mask)+cumsum(suffix_mask)-1`，使用有效prefix数量，而不是无条件使用prefix tensor长度151。

本次用同一模型、同一xt/time比较完整forward与prefix缓存+suffix forward，最大输出差约2.086163e-06；是float32计算路径的细微差，不需强求逐位相等。两个cache叶子都是`[4,4,151,1,16]`，轴分别为layer、batch、prefix position、KV head、head dim。模型sample_actions自行维护缓存，不需要为每次采样把cache保存为checkpoint。

`sample_actions(rng,observation,*,num_steps=10,noise=None)`为Pi0方法，返回`[B,50,32]`动作块；num_steps决定Euler步长、noise可固定初始条件。源码使用 `jax.lax.while_loop`，carry是(x,time)，从time1开始，dt=-.1；while停止阈值为time≥−dt/2，防止浮点误差造成步数偏差。模型参数不在采样中更新。输出仍位于训练动作表示空间，需后处理；不能直接将32个数字交给真实机器人控制器。

## 11. Flow loss与数据后处理的接口【必须会】

`compute_loss(rng,observation,actions,*,train=False)`不是“predict clean actions”。官方key split产生preprocess/noise/time三个key；time~Beta(1.5,1)×.999+.001；code-time1更靠近noise，因此倾向更多训练较噪的位置。换成论文τ=1−s后方向反过来，但两者的中间动作与target同时匹配。

本demo重建相同key的noise、time，执行同一个官方prefix/suffix模型，手算 `mean((v-(noise-actions))²,axis=-1)` 与官方loss一致，shape `[4,50]`。上层`scripts/train.py`在loss_fn中`jnp.mean(chunked_loss)`得到标量，再用config.trainable_filter只微分可训练params；Optax.update产生更新，nnx.update写回模型。训练分布的每个动作维都参与此loss，Pi0这里没有RDT式128槽位action_mask参数。

`train=True`在compute_loss中用于训练时图像预处理；eval/梯度/optimizer是另一层概念。本demo设置train=False关闭图像crop/颜色增强，仍运行value_and_grad与优化器。不能因为这个布尔参数False就说没有训练，也不能说完整官方training pipeline已经运行。本次用合成数据、没有调用LeRobot/data_loader。

部署转换也不能混成flow公式：`DeltaActions(mask)`仅在指定前dims上执行actions−state，原地写回data字典；`AbsoluteActions(mask)`反向加state。例state=[.2,.4]、absolute action=[.5,.6]、mask=[True,False]，delta=[.3,.6]，反向恢复[.5,.6]。第二项不是差分，所以不能所有维都加state。`Normalize`默认z-score为(x−mean)/(std+1e−6)，也有quantile分支；Unnormalize需与同一stats/配置匹配。`PadStatesAndActions`补齐到模型action_dim；padding不是新增机器人自由度。

当前训练配置同时列出 `pi0_aloha` 与 `pi05_aloha`，前者Pi0Config()、后者pi05=True；同一仓库包含后续模型，版本固定仍须选对配置。精读本篇不把π₀.5的state tokenization或FAST离散动作变成原始π₀的贡献。
